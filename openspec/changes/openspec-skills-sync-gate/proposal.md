# Proposal

## Why

The OpenSpec workflow skills in `.agents/skills/` are generated by the `@fission-ai/openspec` CLI (`openspec init` / `openspec update`), but nothing detects when the committed generated files fall behind the installed CLI version. Renovate updates the CLI package routinely (patches and dev-minors automerge), so the committed skills silently drift out of sync with the CLI they document. The natural fix — a Renovate post-upgrade task that runs `openspec update` — is not available: post-upgrade commands are blocked on the Mend-hosted Renovate app, and `allowedCommands` is a global-only option that a repository config cannot set. CI is therefore the enforcement point for this invariant — and, with the auto-regeneration job, its remedy point.

## What Changes

- Add one step to the `openspec` job in `.github/workflows/ci.yaml`: run `openspec update --dry-run --json` and fail the job when the reported `changes` array is non-empty. The command exits 0 even while files are stale, so the step asserts on the JSON output rather than the exit code.
- Change the triggers of `.github/workflows/ci.yaml`: drop the `pull_request` trigger and add a `workflow_dispatch` trigger with a `pr_title` input. The pipeline's PR runs then happen only via explicit dispatches, on the branch given as `ref`.
- Move the `lint-pr-title` job from `.github/workflows/commitlint.yaml` into `ci.yaml`, gated on `workflow_dispatch` with a non-empty `pr_title` input, so all three required checks (`lint-and-test`, `openspec`, `lint-pr-title`) run in the single retriggered pipeline. `commitlint.yaml` keeps only its push-to-`main` `lint-commits` job.
- Add `.github/workflows/openspec-regenerate.yaml`: on `pull_request` (opened/synchronize/reopened) to `main`, check out the PR head branch, and if the generated files are stale, run `openspec update`, commit the regenerated files, and push to the PR branch with `GITHUB_TOKEN`; then, for **every** PR, re-trigger the CI pipeline on the (possibly fixed) head via `gh workflow run ci.yaml --ref … -f pr_title=…`.

## Impact

- Three workflow files: `.github/workflows/ci.yaml` (one new step, trigger change, one moved job), `.github/workflows/commitlint.yaml` (one removed job and trigger), and the new `.github/workflows/openspec-regenerate.yaml`.
- Effect: any PR — including Renovate's own — that updates `@fission-ai/openspec` without regenerating the skills is automatically healed: a bot commit with the regenerated files (all `openspec-*/SKILL.md` files plus the `.agents/skills/.openspec-target` marker) lands on the PR branch, and the CI pipeline runs on the updated head, where it is green and Renovate's platform automerge proceeds as usual. Because the pipeline's PR runs happen only via this retrigger, all three required checks always run on the (possibly fixed) head — never on a stale head about to be superseded.
- The required-checks set in branch protection is **unchanged**: `lint-and-test`, `openspec`, and `lint-pr-title` remain the requirements, and all three are now produced by the single retriggered pipeline.
- The CI gate remains the backstop: if the auto-regeneration job does not run or fails, a stale PR has no green pipeline run and cannot merge.
- Negligible runtime cost: one extra OpenSpec CLI invocation per PR in the regenerate job.
